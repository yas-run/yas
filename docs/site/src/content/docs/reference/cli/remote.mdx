Manage named remotes

Named remotes let you refer to frequently-used destinations by a short name instead of a full URI. They are stored in the home server's `remotes` key/value entry, readable by every client of that server, and one can be set as the CLI default target with `yas remote set-default`.

Examples:

```text
yas remote add rabbit ssh:rabbit
yas remote add prod ssh:alice@prod.example.com
yas remote add lab share:mysecret
yas remote add sandbox 'uplink:https://relay.example#token=TOKEN&server=PUBLIC_KEY' # uses YAS_UPLINK_IDENTITY
yas remote list
yas remote remove rabbit
yas --on rabbit terminal list
yas remote set-default rabbit
```

```text
Usage: yas remote [OPTIONS] [COMMAND]
```

## yas remote list

List all named remotes.

```text
Usage: yas remote list [OPTIONS]
```

Options:

- `--reveal`

  Show embedded credentials in full instead of masking them

## yas remote add

Add or update a named remote.

```text
Usage: yas remote add [OPTIONS] <NAME> [URI]
```

Arguments:

- `<NAME>`

  Name for the remote

- `[URI]`

  URI to connect to (ssh:host, tcp:h:p, socket:/p, share:pass, local). Omit to be prompted interactively

## yas remote remove

Remove a named remote.

```text
Usage: yas remote remove [OPTIONS] <NAME>
```

Arguments:

- `<NAME>`

  Name of the remote to remove

## yas remote toggle

Disable or enable a named remote without removing it. Disabled remotes stay in the catalogue and are excluded from connection resolution until re-enabled.

```text
Usage: yas remote toggle [OPTIONS] <NAME>
```

Arguments:

- `<NAME>`

  Name of the remote to toggle

## yas remote set-default

Set the default remote in yas.conf

After this, all agent subcommands (list, start, show, …) will connect to this remote by default, without needing `--on`.

```text
Usage: yas remote set-default [OPTIONS] <TARGET>
```

Arguments:

- `<TARGET>`

  Name or URI to use as the default target. Pass an empty string or "local" to reset to local
